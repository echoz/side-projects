Behind the glow

A small screen.
A thoughtful system.

One long-lived Swift host coordinates separate plugin processes. Sources supply facts, a provider chooses what matters, and Marquee keeps the pixels up to date.

  1. 1

    Bring the context.

    Source plugins publish typed facts and updates. Separate Codex and Claude plugins publish allowance readings through the host’s scheduled polling. The automatic simulator walkthrough uses scripted quota and workout observations.

  2. 2

    Choose the moment.

    The default heuristic or an optional model provider selects a complete host-prepared screen or continues an existing selection. The model does not draw pixels or author layouts; the host owns disclosure, turn timing, formatting and reflow.

  3. 3

    Give it some glow.

    A display plugin receives the rendered frame: USB to a WLED TC001, or a local SVG simulator with a read-only true-color terminal viewer. Cached dependencies allow USB output and the simulator to work without a network.

Automatic and manual billboards

Synthetic quota → workout → quota, live progress, privacy filtering, fallback and manual override run through real source, provider and simulator processes. The CLI and Swift client share the host’s control path.

EXERCISED / PHYSICAL DEVICE

TC001 over USB

Text, replace/clear and a text/progress demo have been user-confirmed on the physical display. The software also has a local SVG simulator and terminal viewer. Device observations and software tests are separate evidence; unattended reliability is not established.

EXERCISED / BOUNDED LIVE CHECKS

Claude and Codex account setup

Codex sign-in, saved connections after restart and allowance reads were exercised on macOS. Claude sign-in, saved workspace discovery and two scheduled allowance reads were exercised separately. Claude uses unofficial web interfaces. One Codex trial produced a visible TC001 allowance percentage. Sustained unattended use and Claude output on TC001 still need verification.

OPTIONAL / QUALITY UNDER EVALUATION

Model-backed selection

Configurable model providers support Chat Completions and Responses. Bounded synthetic trials demonstrate accepted selections and live bindings. Valid replies alone do not establish good judgment, useful rotation, acceptable latency or unattended readiness.

Separate kinds of evidence: Software tests exercise synthetic inputs and test-owned resources. Live account and display trials have their own verification limits; neither establishes unattended reliability.
