Behind the glow

A small screen.
A thoughtful system.

One long-lived Swift host coordinates separate plugin processes. Sources supply facts, a provider chooses what matters, and Marquee keeps the pixels up to date.

  1. 1

    Bring the context.

    Source plugins publish typed facts and updates. The working automatic demo uses scripted quota and workout observations. Claude and Codex allowance plugins are in development: account setup and on-demand reads exist, but automatic polling and fact publication are still ahead.

  2. 2

    Choose the moment.

    The default heuristic or an optional model provider selects a complete host-prepared screen or continues an existing selection. The model does not draw pixels or author layouts; the host owns disclosure, turn timing, formatting and reflow.

  3. 3

    Give it some glow.

    A display plugin receives the rendered frame: USB to a WLED TC001, or a local SVG simulator with a read-only true-color terminal viewer. Cached dependencies allow USB output and the simulator to work without a network.

Text, replace/clear and a text/progress demo have been user-confirmed on the physical display. The software also has a local SVG simulator and terminal viewer. Device observations and software tests are separate evidence; unattended reliability is not established.

IMPLEMENTED / LIVE CHECKS PENDING

Claude and Codex account setup

The shared isolated-browser flow has software coverage for validation, retries, cancellation and host-owned credential saving. Earlier Claude sign-in, discovery, reuse after restart and one allowance read worked live. The new flow needs fresh live checks; Codex sign-in and quota access remain unverified. These integrations use unofficial web interfaces.

OPTIONAL / QUALITY UNDER EVALUATION

Model-backed selection

Configurable model providers support Chat Completions and Responses. Bounded synthetic trials demonstrate accepted selections and live bindings. Valid replies alone do not establish good judgment, useful rotation, acceptable latency or unattended readiness.

Latest software checkpoint: 1,469 tests passed across 204 suites on macOS. The suite exercises synthetic inputs and test-owned resources, not live subscription access or physical-display reliability. Isolated sign-in requires the bundled marquee-browser helper alongside marquee.

The roadmap

Where we go next.

Build on the working billboard, one useful slice at a time. These are directions, not release dates; later work has no fixed order.

  1. NEXT
    Live verification

    Finish proving account sign-in.

    Exercise Codex sign-in, account discovery and an on-demand allowance read. Recheck Claude through the shared browser flow, including the visible sign-in experience. Keep the distinction between accepted credentials and successful allowance access.

  2. PLANNED
    Live allowance screens

    Turn account readings into live facts.

    Settle how resets and stale or missing readings behave, then connect automatic polling and fact publication to the existing billboard. Consumption-rate and time-to-quota estimates still need a calculation policy. None of these live automatic quota features are implemented yet.

  3. LATER
    Broader capabilities

    More context. More ways to show it.

    • Workout sources, richer adaptive widgets and animation.
    • TC002 support, device discovery and calibration.
    • Automatic USB/plugin recovery and managed plugin installation.
    • Simulator recording/playback and Linux/Windows native adapters.

    Broader model comparisons and selection-quality evaluation also remain ongoing work. Software-test coverage is not a promise of unattended readiness.
