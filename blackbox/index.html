LOGBOOK 01 / THE OWNERSHIP MODEL

A record of where
the record came from.

Blackbox reads Garmin’s unofficial private interfaces. Retrieval serves committed local data; a query never calls Garmin.

  1. 01 / RECOVERY AUTHORITY

    Immutable source archive

    Each committed observation has its own receipt. Identical payload bytes share one content object. Exact source bytes and their provenance remain under the owner’s control.

    Local storage / content deduplication
  2. 02 / REBUILDABLE LOCAL VIEW

    Rebuildable SQLite

    Installed importers turn supported archived responses into daily summaries. SQLite is a query projection: supported archives can reconstruct it locally, without another download.

    Source acceptance ≠ import success
  3. 03 / QUERY + OBSERVE

    Local API & terminal

    The daemon owns storage. A scriptable CLI retrieves summaries, coverage, failures and artifacts. A private Chio monitor receives pushed status and run observations, with explicit history browsing.

    REST / blackboxctl / read-only monitor

LOGBOOK 04 / OPERATING BOUNDARIES

One owner. Local storage.

A Swift service with explicit storage ownership and local clients.

Linux / Docker target

Swift 6.4 with strict concurrency. Native development requires macOS 15 or newer. The service image contains the daemon and CLI; the private monitor is built separately.

Explicit local setup

Use owner-controlled local POSIX storage, restricted credential files, and a named IANA time zone. Current archive-v2 setup takes no historical start date. Earlier archive or SQLite formats are refused without automatic conversion or deletion.

Unofficial, read-only access

Garmin’s private interfaces are unsupported and can change. Blackbox does not modify Garmin records or bypass challenges or rate limits. The supported API publication is loopback-only; wider access needs a separately reviewed secure boundary.
